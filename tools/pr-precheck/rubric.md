# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The plan-context block's scope statement, named files, test plan, and deferral notes; the candidate PR's changed-file list, hunks, and commit summaries; the candidate title and description's claims about files, behavior, tests, and scope. In live mode: `plan.md` including `## Deviations`, the committed `git diff` from the target base, and the draft title and description. | Pass only if all three hold: (a) every changed file and every changed behavior is inside the plan's stated scope; (b) every deliverable the plan names is present in the diff, or is explicitly deferred in the plan's deferral notes or in a description deviation note that names the missing work and gives a reason; and (c) every description claim about files, behavior, tests, or scope is true of the diff and the evidence. A deviation note re-ties a mismatch only when it names the extra or missing work and why it is there. Judge scope and behavior, not the exact line placement of a named change: a plan that names a function and a mechanism is satisfied by an equivalent implementation at the nearest sensible point in that function. A plan's statement that an untouched caller keeps its behavior is not a missing hunk; fail only when a changed file or behavior exceeds the boundary. Fail for any unplanned file, option, config, flag, refactor, rename, or behavior; any absent plan deliverable; or any description claim the diff contradicts. Tests, docs, changelog, i18n, and other files named in the plan or required by a repo ask are in scope. | required |
| decisive-test-evidence | The candidate PR's test-evidence section and the description's before/after lines, read against the plan-context block's test plan and the issue reproduction's steps; the repo-facts block's stated checks and test commands. In live mode: `test_evidence.md`, captured terminal output, CI, and the diff's test assertions. | Pass only if the package shows (a) an observable before state and after state for the issue's reproduction or the plan's primary test, using the same command, input, and failure path as the issue, with the observed result that distinguishes them (output, exit code, state, or assertion); and (b) the repo's stated check or test suite named with its result, or a disclosed reason a required check could not run. A failing-before and passing-after test counts when its assertion or output is shown. Condensed transcripts count when they name the command or input and both observed states; pasted output is preferred but a named command with a stated result counts. When the plan names a primary reproduction plus secondary checks, the primary reproduction must show before/after; the secondary checks may be covered by a new test assertion plus the named passing suite. Fail for "tests pass", "tested locally", screenshots or prose with no observable behavior, evidence from a neighboring property or wrong path (wrong request method, wrong casing, a single-file control when the bug is cross-file), only the after state, or a plan with distinct material failure modes where the evidence covers only one and no deferral is stated. If the plan explicitly defers a subcase, evidence for the remaining behavior plus the stated deferral passes. | required |
| reviewable-diff | The unified diff's changed-file list and added and removed lines, plus the commit summary. In live mode: `git diff` against the target base and `git log`. | Pass only if the fix or behavior change is visible in the diff and the diff carries no debris or unrelated change: no debug output left in (print, eprintln, console.log, dbg!, System.debug, or fmt.Println, including commented-out calls), no commented-out code, no dead or unused functions, imports, variables, or constants, no TODO or FIXME left on the changed path, no whitespace-only, re-indentation, import-reordering, or formatting-only hunk, and no changed file or hunk unrelated to the plan. Explanatory comments, tests named by the plan, and changelog, docs, or i18n files required by the plan or repo are not debris. A refactor the plan names is in scope. Do not fail for an unchanged line repeated around a real behavior change, for a helper a new test calls that already exists outside the excerpt, or for a bundle excerpt whose hunk header line counts do not match the displayed lines; judge the lines shown. | required |
| template-and-policy | The repo-facts block's PR-template asks and contribution policy, and in live mode `.github/PULL_REQUEST_TEMPLATE.md`, `CONTRIBUTING.md`, and any `AI_POLICY.md`; the candidate title and description; the diff for artifacts the asks name (changelog, whatsnew, docs, tests, i18n, cheatsheets). | Pass if every ask the repo states for this PR is visibly satisfied: required sections filled with specific content, required checklist lines present, the issue link or closing line present, and the named changelog, whatsnew, docs, test, i18n, or cheatsheet artifact present when required; the title follows a stated convention. If the repo states no template or asks, pass. Fail for a required section absent or boilerplate, a required closing link missing, a required artifact absent from the diff, or an ignored checklist item. Do not fail for a section the repo does not ask for, for length, or for a missing screenshot when the ask is conditional and the change has no visible surface. | required |
| ai-disclosure | The repo-facts block's stated AI policy, and in live mode `AI_POLICY.md` or the contribution policy; the candidate description. | If the repo states no AI policy, pass. If the policy requires disclosure, pass only if the description discloses AI assistance in the form the policy requires, naming the tool or assistance and its extent in the author's own words. Fail if a required disclosure is absent, or if it is a bare "AI-assisted" that omits a required tool or extent. If the policy forbids AI use, an admission of AI use fails. Do not infer a policy the repo-facts block does not state. | required |

## Verdict rule

Accept only if every required check passes. A single `fail` or
`unclear` on a required check means `reject`; there is no third verdict
and no partial credit. Preferred checks, if any, never change the
verdict. An unverifiable claim is a failing claim: if the package does
not carry the evidence a check names, grade that check `fail` and say
what was missing, rather than assuming the missing fact.

When more than one check fails, the summary quotes the first failing
required check in rubric order; the JSON still reports every check.
