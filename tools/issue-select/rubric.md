# Rubric: is this a good first issue?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Maintainer activity | In the repo-facts block, inspect the dates of the last 5 default-branch commits and the maintainer first-response sample. In the issue comment thread, inspect recent comments by a repository maintainer or owner. | Pass if at least 1 of the last 5 default-branch commits is dated within 180 days of the issue snapshot date, or a maintainer/owner comment is dated within 90 days of the issue snapshot date. Fail if both signals are older than those thresholds. Mark unclear only if the bundle provides neither commit dates nor comment authors/dates. | required |
| Repository use | In the repo-facts block, inspect open issues, open pull requests, releases, dependents, or recent default-branch commits. | Pass if the repo-facts block shows at least 1 concrete current-use signal: an open pull request, a release within the last 365 days, at least 10 open issues, at least 1 dependent, or a default-branch commit within 180 days. Fail if every provided use signal is absent or stale. Mark unclear only if none of these facts are supplied. | required |
| AI contribution policy | In the repo-facts block, look specifically at the `contribution policy` line. Check whether the repository explicitly bans, rejects, or prohibits AI-generated code or contributions. | Pass if the repository has no contribution policy, or explicitly allows/welcomes AI assistance (even with standard requirements to test, review, and understand changes). Fail if the repository explicitly bans or rejects AI-generated contributions (for example: "We do not accept AI-generated code or documentation", as seen in BookWyrm). | required |
| Active claim or contested thread | In the repo-facts block, inspect the `linked_prs` list. In the issue body and comments, inspect assignees, comment dates, and contributor claim comments. | Pass if there are NO open linked pull requests (`"state": "open"`), no active assignee, and the issue is not currently claimed or contested. Fail if: (1) any linked pull request has `"state": "open"`, or (2) an assignee is present, or (3) the issue has a contested history with more than 15 total comments or repeated claim attempts, or (4) the latest comment in the thread is a contributor claiming the issue (e.g. `@zulipbot claim`) without an explicit unassignment or abandonment. Note: closed pull requests on clean, uncontested issues (such as issue-09 with 4 comments) pass this check. | required |
| Actionable bug or feature | In the issue author, title, body, and labels, inspect whether the request is a concrete bug report, documentation addition, or defined feature. | Pass if the issue describes an observable problem, bug, documentation gap, or a well-scoped feature request with clear behavior. Fail if the issue author is an automated bot (such as `cursor[bot]`) proposing arbitrary enhancements without human maintainer endorsement, or if it is an untriaged feature request lacking any label and created by a bot. | required |
| Bounded newcomer scope | In the issue title, body, and labels, assess the work required. | Pass if the task addresses a concrete bug, UI freeze, missing preview, documentation update, or bounded feature request. Fail if the issue explicitly asks for a massive multi-year architectural migration, a repository-wide mega-issue tracking dozens of separate items, or rewriting whole systems from scratch. An issue describing multiple potential root causes or optimization ideas for a single concrete bug (e.g., UI freeze) remains bounded and passes. | required |
| First-timer friendliness | In the issue body, labels, and comments, look for `good first issue`, `help wanted`, `beginner`, or maintainer implementation guidance. | Pass if any beginner label or maintainer guidance is present; fail otherwise. | preferred |

## Verdict rule

Accept only if every required check passes. Reject if any required check fails or is unclear. Preferred checks never change the accept/reject decision; they only rank accepted issues.
